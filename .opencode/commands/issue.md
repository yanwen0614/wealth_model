使用场景：正在处理其他任务时发现了一个问题，说一句"把上文的 xxx 问题记录一下"。
直接从对话上下文提取问题信息，不额外做代码探查。

> issue 文档存放于 `docs/agent/issue/{yyyyMMdd}_{issue-tag}/issue.md`（quant-model 通用，兼容 cnn 项目；关联 quant-model / cnn-harness 流水线）

## 执行步骤

### Phase 0: 从上下文提取问题 + 生成 issue 文档

1. 从对话上下文提取：
   - **问题标题**（中文 + 英文 kebab）
   - **问题级别** P1/P2/P3（根据严重程度）
   - **背景**：问题发现场景
   - **问题描述**：核心现象 + 证据（引用上文的日志/数据/代码）
   - **根因**（已知则写，未知则写"待确认"）
   - **影响评估**：表格列出受影响的模块与程度
   - **来源**：引用发现此问题的 task 文档或 commit

2. 生成 task_dir = `docs/agent/issue/{yyyyMMdd}_{issue-tag}/`
   - 日期取当天
   - issue-tag 取英文 kebab 短标识

3. 写入 `{task_dir}/issue.md`，参考 TEMPLATE.md：

```markdown
# <中文标题>（<english-kebab>）

> 创建日期：YYYY-MM-DD
> 级别：P1 / P2 / P3
> 状态：待处理 / 待决策 / 评估完成
> 来源：<当前任务文档路径>

---

## 一、背景

从上下文中提取的问题发现场景。

## 二、问题描述

核心现象 + 证据（日志/数据/代码引用）。

## 三、根因

已知则写，未知则写"待确认"。

## 四、影响评估

| 影响面 | 程度 | 说明 |

## 五、方案选项（可选）

## 六、验证方式（可选）

---

## 任务关联

> 发现自 `<当前任务文档路径>`。
```

### Phase 1: 展示确认

1. 展示 issue 关键信息
2. 等待用户确认或修改

## Red Flags

| 错误行为 | 纠正 |
|----------|------|
| 状态开始就写"已解决" | 初始状态必须为"待处理"或"待决策" |
| 离开当前上下文去探查代码 | 不额外做代码探查，只从已有上下文提取 |
| 影响评估用主观描述 | 必须用表格 + 程度标签 |
