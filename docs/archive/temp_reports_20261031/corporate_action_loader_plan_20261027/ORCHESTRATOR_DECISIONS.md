# 主会话实施裁定

- 批准在新的独立工作树实现 loader/context 模块及其测试；不与运行器 owner 同时修改同一个 runner 文件，不改 core。
- 规范事件优先使用源字段 `每股送转=T` 的总送转比例，不以 C 回退 T，不将 T+B+C 相加。B/C 是原始分项来源，不改变总权益。
- 同方案现金与总送转尽量用一个复合事件，避免两次股权成本分配；有 B 的混合方案不得标成“已知免税转增”，税务未知如实保留。
- RecordPosition 必须由 core 在登记日收盘写入。不能用当天开盘前持股判断是否产生登记操作。
- 仅在 record_date 严格早于 reset anchor 且已声明空仓初始账户时，缺 record 操作可按未取得权益跳过；anchor 后本应有记录而缺失，必须 fail closed。
- 登记数量为零时，后续阶段跳过创建、付款、上市，避免零权益幽灵对象。可先保证此不变量；无需同时改既有 bridge。
- 登记后当前仓位变为零不抹除现金权益。股权情形遵守 core“登记与除权前数量不变”的现有约束；不支持的路径明确 INCOMPLETE，不能造成本账。
- 真实登记数乘总送转比例为整数时，采用“无需舍入的精确整股路径”；这不是发行人零碎股规则证书。非整数、浮点无法精确表达或正权益缺上市日等情形停止并留证。
- 送股税/转增税未知：严格模式对实际暴露 fail closed；显式探索模式可输出机械账及 unknown 状态，但不得标成实际税后达标。现金20%仅为压力场景。
- 有 record_date 但缺 ex_date 的原始行不能静默消失；作为 unresolved descriptor 登记与追踪，有正登记暴露即 INCOMPLETE。1/2等完全缺阶段的方案不凭进度码编造日期。
- 配股表只有公告日；固定策略不认购，保存覆盖缺口，不伪造配股阶段或新股入账。
- loader/context 交付后独立质量门通过，主会话再安排运行器 owner 接入 observer/hook。不要在两个工作树各复制一套 runner 或现金账。
