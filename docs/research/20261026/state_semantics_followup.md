## 稀疏事件表的正确解释

SQL history_status设计为只保存异常，正常日无行不是数据缺失证据。
只有该代码查询窗口完整成功且原始行完整时，无异常行才可据源契约解释为正常。
现有管道仍有SDK空结果/缺key、generic静默丢码及空dict被当整批无事件的例外；touch不含逐日请求账。
所以目前应称部分范围覆盖未核实，不能直接称4014只不存在状态数据，也不静默填正常。
