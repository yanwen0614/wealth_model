# 保守开盘执行政策：独立机制审查

## 结论
- **对原先“看到最终open后再决定同open成交”的版本维持NO-GO。** 最终集合竞价open确定时，开盘撮合已发生，事后条件选择不能撤销或新增该次撮合。
- 用户提出的因果修正版不同：close时预先生成带固定股数和价格限价的次日订单，订单在集合竞价前已存在；执行日open只用来检验已存在订单是否满足限价。这个时间顺序可作因果的开盘撮合模拟，仍不证明实际队列成交。
- **4.5%统一带可减少对历史ST标签的依赖**：政策直接检查价格和已验证reference，无需把ST缺失填为非ST。它是自定筛选政策，不判定法定涨跌停、不等同实际成交，也不能叫收益下界或普遍更差。

## 现有输入与“unknown”语义
- 当前 [market.py](D:/code/cnn_full_20260905/cnn/backtest/cnn_adapter/market.py:74) 只读后复权OHLC、volume、amount及交易标志；它没有raw open/reference字段。当前接口不能直接执行用户所述raw价格门，须由正式行情源提供可溯源raw价格和公司行动调整后的reference。
- 现有 `_derive_limits` 在不能判定时增加 `limit_unknown_count`，但返回 `(False, False)` 占位；[tradability.py](D:/code/cnn_full_20260905/backtest-core/src/backtest_core/policies/tradability.py:84) 会把两项false视为可进入执行层。这是“unknown被误当允许”的接口风险，不能复用为新政策的通过状态。
- 分开记录三种结果：①法定限价/ST状态 `unknown`；②reference或raw open缺失/未验证，按政策拒单；③价格带检查通过，仅表示可尝试/回放假设，不表示实际成交已证明。拒单原因分别标识，不能把unknown伪装成涨跌停，也不能因4.5%通过而写成法定状态已知。
- 若策略定义为遇到“法定限价状态unknown”一律拒单，则缺历史ST数据仍会阻断样本；这与用统一4.5%政策降低ST依赖的目的冲突。建议ST仍保留unknown，仅用自定价带裁决是否进入政策尝试路径。另，现有provider的`st_codes=None`会变为空集合并按非ST幅度推导（[market.py](D:/code/cnn_full_20260905/cnn/backtest/cnn_adapter/market.py:232)、:237、:339）；不得把这条默认路径用于缺历史ST状态的数据。

## 例外和执行边界
- 执行条件应为：raw open及reference均有效且已验证、raw open严格大于1元、相对reference的绝对变动严格小于4.5%，并留足报价最小跳动余量；任一条件不满足则该次不开新仓/不卖出。4.5%是自定门槛，不推导实际涨跌停价。
- 除权除息日不能盲用前收作reference；必须取得并核验交易所/数据源的当日除权参考价及有效时间。停牌、缺bar、复牌/重新上市、IPO无涨跌幅日、板块/规则转换等仍需有“是否可取得有效raw价与reference”的处理；另需确认历史是否存在适用幅度小于4.5%的特殊交易日，未排除前不能声称处于法定限价内。本政策对这些情形不推断法定限价状态。未知reference一律拒单并保留持仓，不回溯剔除股票。
- 原绝对双边变动门不作为修正版规则：普通买入限价只给上限、卖出限价只给下限；反方向价格变化超出另一侧，不代表该侧不能成交。修正版按订单方向裁决：买入open≤预设买入上限，卖出open≥预设卖出下限。
- 超带拒绝的卖单应保持持仓并按冻结规则后续重试；停牌、跌停、T+1锁定及尾日未卖出都不得伪记清仓。新开仓拒绝则不建仓。队列/容量限制仍是单独成交假设。

## 固定不参与配股
- 若规则明确“不认购配股”，普通股股数维持原数；当日股票部分raw市值可记为 `原始股数 × 当日raw价格`，计算这项股票市值本身不需要配股缴款日或配股比例分母。
- 这不自动等于完整账户财富：配股权利是否产生、何时归属/注销、是否可交易或有现金处置，以及不认购后权利到期如何入账，属于独立权利/现金流契约。若权利按政策无偿放弃，须明示放弃时点和价值处理；若有可回收款/可交易权利，须核账，不能漏掉或凭空加股、加现金。
- 即使不认购，除权reference及开盘价带仍可能依赖配股条款/交易所除权价。故“股数不变”可先定义持仓政策，但不能替代公司行动reference核验。此处只审机制接口，不重复公司行动数据库盘点；细节由公司行动契约会话闭环。

## 主会话可执行门槛（仅政策机制，不是绩效放行）
- **GO（仅进入政策实现/合成验证）**：冻结4.5%公式、边界严格性、tick余量、raw价>1、reference来源/时点及缺失拒单语义；每日输出原始输入、reference溯源、政策检查结果、拒单原因和持仓状态；ST字段可保持unknown，不填造标签。
- **NO-GO（因果订单模拟）**：执行日open后才创建/改写该订单或目标股数；成交价越过订单限价；买单预算没有按最坏限价和费用预留；用后复权open代替raw open；reference在订单有效前未验证；unknown经false/默认非ST而放行。
- 日线开盘模拟可使用raw open判定既存订单是否价内，并使用预先冻结的容量/队列假设；应标明“受限开盘执行模拟”。不需要把缺L2解释成无法做任何研究，但需明确它不保证实际排队成交，不称实际成交已证明或收益下界。
- 配股政策GO条件：原股数与新增股数、权利、缴款、注销/到期现金流分账；reference验证失败时拒绝该日交易；股票raw市值与未结权利分列。任何上述口径未闭环，只阻断相关公司行动日/交易与财富闭合，不得把所有其他历史日期一概判为不可研究。

## 因果修正版：固定限价订单的受限开盘基线
- **机制判断：有条件GO，可推进日线+明确容量假设的受限开盘执行基线。** 信号日收盘固定数量、费率预算和订单边界，订单在次日集合竞价前已生成；撮合器用官方raw open检验这张既存订单是否价内，再应用容量和滑点。这样不存在“观察开盘后才创建订单”的事后选择。
- 当前生产契约尚不能直接承载该机制：`OrderIntent`只有代码、方向、股数/cash预算（[order.py](D:/code/cnn_full_20260905/backtest-core/src/backtest_core/contracts/order.py:35)），`_plan_order`做滑点/容量计划但没有限价不变量（[account_runner.py](D:/code/cnn_full_20260905/backtest-core/src/backtest_core/engine/account_runner.py:296)）。因此是机制GO、现有实现NO-GO；先补订单/成交契约与验证，不修改生产代码属于本次只读审查范围。
- 买单上限为 `floor_to_tick(reference×1.045 − tick_margin)`，只检查 `raw_open≤buy_limit`；卖单下限为 `ceil_to_tick(reference×0.955 + tick_margin)`，只检查 `raw_open≥sell_limit`。raw open须>1元；reference和tick规则须有效。反方向封板不单独证明买/卖侧不可成交。
- 买入目标股数在信号日按该限价下的最坏成交额加已知买入费率预算，向下取整并预留现金；卖出数量按信号日已知持仓及预期可卖量固定。看到执行open后不得改目标数量。预开盘正式更新reference时，记录更新来源/时刻，按新reference重算限价；数量不变，若预算不再覆盖最坏成本则取消订单。
- 价内只是撮合资格。估算滑点后的买入价必须≤buy_limit，卖出价必须≥sell_limit；越界则拒绝该次成交，不能先记账再截价。容量只使用信号时已知历史数据形成的预定cap；partial/remainder按预定生命周期记录，未成交余量到期后才可用固定余量重试，不重算目标量。
- 这构成“交易所看到一张预先存在、价格合格的限价单时，按open及明确容量模型撮合”的**合法成交模拟条件**；不证明排队位置、实际开盘可用量或实盘成交。日线缺L2限制的是成交证据强度，不阻止这个受限基线研究。它不是收益下界，也不代表普遍更差。

### 最小订单/成交字段
- 订单：`parent_order_id`、证券代码、方向、信号时间、订单生成/提交时间、有效交易日与到期时点、固定原始股数及剩余股数、买入上限/卖出下限、费用表版本、买单最坏现金预留。
- Reference 溯源：reference值/来源记录ID、已知时间、适用/生效日、raw报价单位与tick规则版本；如有开盘前正式更新，保留前后值、更新时间及原因，股数保持不变。
- 撮合记录：官方raw open、open是否价内、预估滑点后价、成交股数/价、历史ADV/cap来源与参与率、状态（filled/partial/rejected/expired）及明确拒因；公司行动事件gate结果独立留痕。

### 必须通过的机制测试
1. 时间顺序：信号收盘生成订单；执行open只读已存订单，不能改股数/方向；任何open后才创建或改量的路径拒绝。
2. 价格边界：买入上限、卖出下限分别测试边界内/等于/越界，tick取整和严格留tick；买单只受上限、卖单只受下限，反方向大幅有利open不误拒。
3. 滑点/预算：最坏限价含费用不超已预留现金；模拟滑点后价超限则零成交/明示拒绝；容量截断partial与剩余量、现金和持仓守恒。
4. Reference事件：普通日引用已存在有效reference；公司行动只允许使用开盘前已知且生效的正式更新；未知、未来生效、缺值或来源冲突均开盘前拒单，不按未来结果回溯筛选日期。
5. 生命周期：卖出固定数量不得超过实际可卖/T+1约束；未成交卖出保留持仓并按规则重试，未成交买入不建立持仓；末日残仓不伪报清算。
6. 信息边界：容量/滑点估计不读执行日全日volume/amount；状态日志区分“价内/可尝试”“模型成交”和“实盘成交证据”。

### 放行边界
- **GO**：用正式raw open与可溯源reference，订单在集合竞价前生成；股数、费用预算、限价和订单有效期冻结；reference事件gate无前视；模拟滑点遵守限价，容量假设显式且能复算。可进入合成/小样本执行机制验证，不涉及绩效放行。
- **NO-GO**：订单无可审计的开盘前生成时间；按观察到的open回填下单/改量；没有raw open/reference；公司行动reference未来筛选；滑点后越价仍记成交；或把日线容量代理/价内判定宣传为真实排队成交证明。
