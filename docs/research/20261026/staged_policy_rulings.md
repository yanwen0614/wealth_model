# 分批策略实施裁定

本裁定补充临时根 `three_day_candidate_registry.md` v1 与 `staged_policy_strategy_plan_20261026/PLAN.md`；尚无候选收益比较，不根据结果选择规则。独立验收夹具见临时根 `staged_policy_independent_oracle_20261026/`。

## 排名和信号

- 当日 `status=ready` 且 `exp_ret` 有限的完整信号宇宙，按预期收益降序、代码升序排序；沿用既有 `CnnOrderStrategy` 并列规则。
- `buy_eligible` 门控所有新提交的BUY，包括已有周期的t3/t6加仓；它不删排名、不限制SELL。半年末E日仍保留完整排名，用于退出与当日计划判定。
- 不得先按行情或状态可用性缩小股票池再重排名；缺rank、缺来源和缺执行数据须分开记因。

## 预算和周期

- 初始资金C固定，完整预算槽B=C/5，最多5个活动周期，不因分红、亏损或半年边界改变B。
- `commitment = B - 累计真实BUY现金借记`。已投入现金不重复从可用现金中扣除，未投及取消金额持续占用至CLOSED。
- C70最多累计投入0.7B（含真实现金费用），剩余0.3B继续占用；完整B槽不代表成交后再扣一次完整B现金。
- 新周期须满足core可用现金减全部活动未投承诺不少于B；不得借其他周期的预留额。
- 同代码非CLOSED周期、持仓、锁仓、未上市权益或活动订单阻止同代码重开。另一代码退出中不构成全局禁开条件，其他代码仍须通过槽位、现金及名额检查。
- 即使t0无成交，未来t3/t6仍在，代码也占其活动周期；不能因同代码开槽失败而中止后续其他代码的合规判断。
- 退出须明确取消全部未来份额；仅标记exit_pending而未取消计划，或只有暂时空仓，均不能提前关闭周期。
- 所有份额终态且持仓、锁仓、未上市权益和活动订单全清后关闭；关闭才释放余款和槽。

## 时钟与订单

- t0、t3、t6为原定交易日收盘决策；初份拒单、零股或部分成交不改变后续日历，不追补DAY余量。
- S2 t3检查t0至t3含端点；t6检查t3之后至t6含端点，t3不重复计入后段。
- 日期推进与收盘finalize分开，t6上午快照不能终结尚未处理的t6收盘份额。
- BUY限价为T日raw close×1.045按tick向下，SELL限价为T日raw close×0.955按tick向上；信号时冻结整数股及费用预算。
- T日法定界不是T+1法定界，不以T日上下界夹改次日委托。执行日真实法定界由core独立检查，未知或越界拒单，不夹成交价或追单。
- DAY由冻结core的真实runner一次性取出排程及终态反馈证明；不臆造不存在的TIF字段，仍须合成端到端留证。
- 实际正持股代码始终不超过10；权益及活动BUY按代码并集保守占位，未确认卖出不腾空位。

## 终端与验证

- E日收盘禁止任何次日进入buffer的BUY，为仍持有的可卖股份排首次buffer开盘SELL；保留episode/order身份、固定shares和限价。
- buffer最多3个市场交易日，只允许卖出/清算；失败后继续披露持仓、锁仓和权益，不虚构全现金。
- 不能直接套用会重建无episode/limit卖单的旧 `ExitOnlyStrategy` 作为新策略终端路径。
- 半年主收益以E收盘计量，buffer结果另列并用同时间基准；reset实验不得冒充连续账户。
- 先过15条独立规格夹具、真实core账户端到端、Ruff/Pyright与冻结版本QA，再放行有身份和覆盖证据的候选回放。
- 工程通过、条件机械回放与最终盈利要求分别报告，当前目标仍未证明。
