## 2. 请求契约与获取方式

- 日期窗口固定为2020-12-31至2021-07-05（含边界），自然日参数；保留可用的窗口前最近交易日状态/参考价作为开盘判定上下文，实际需用交易所日历明确首日所需previous close。
- 代码清单固定为F4 W1信号代码；附代码市场、挂牌/退市生命期来源和清单SHA。不要仅从当前stock_basic重建历史宇宙。
- 使用现有 `HistoryStatusFetcher` 的 `get_history_stock_status` 接口与SDK环境。源码批量为100码/批、120秒超时、默认最多3轮失败重试、指数退避2/4/8秒（上限30）；单码调用为30秒。接口走 `is_local=True` 与AmazingData本地缓存路径；执行前先确认其读缓存/远端补取语义及账号配额。不得为了本次需求增加API或修改SDK。
- SDK QueryThirdInfo不支持线程安全；严格串行发批，不并发调用。源码未声明QPS/日额度，不能把重试退避当速率配额。遵守服务端限流/配额响应；任何限流、认证/权限错误或连续超时立即停批并记录，不盲目续跑。实际配额/调用授权须先由用户确认。
- 禁止先经 `_process_status_result` 异常过滤：它会丢正常日原始行，且`fillna(0)`会把缺值伪装为False。直接保存SDK原始逐日响应，保留原始字段/类型/状态码/响应批次边界。若SDK只交付稀疏事件行或不能返回完整日行，则该来源不满足本契约，停止并报告，不推断正常日。

## 3. 覆盖证明与失败条件

输出每批请求清单：run_id、代码列表/hash、begin/end、SDK及quant commit、开始/结束UTC时间、调用参数、尝试次数、返回key、异常/响应状态、原始行数、原始日期集合hash、文件hash、输出路径。每码另生成manifest：是否已有HDF、HDF行/文件hash、预期交易日数、实际行数、缺失/多余/重复日、字段空值统计、生命周期例外、最终verified/unknown及理由。

用固定版本沪深交易日历分别核对市场。对在市区间，要求每个预期交易日恰有一条状态快照；上市前/退市后的无行只能由独立生命周期证据解释。返回key缺失、`None`、空DataFrame、全窗0行、日期不符、重复、关键字段缺失、批次未完整落盘均视为失败/unknown；不得映射为无事件/正常。供应商请求状态与内容日历覆盖分开记录。

状态字段保留原义；`IS_WD_SEC` 不解释为退市风险过滤键，`IS_XR_SEC` 不解释为安全状态证明。无法从raw行得到当日昨收/绝对限价或其语义未核定时，reference/limit为unknown，拒绝该股票开盘买卖裁决并报告；不以训练后复权close或touch最新值回填。

建议唯一输出根：`D:/tmp/opencode/state_acquisition/W1_20201231_20210705/`，含 `raw/`（按代码或批分区的原始响应）、`manifest/`（请求批次、逐码coverage、calendar版本）、`logs/`与 `run_summary.json`。只写该独立目录，不写/更新Z盘数据库、quant canonical库、共享HDF缓存或CNN策略产物；先做空间预估，批次完成即fsync/校验hash，再记录成功。
