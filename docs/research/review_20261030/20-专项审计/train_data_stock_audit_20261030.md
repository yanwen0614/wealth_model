### 3.3 与 `dataset.py:160` 过滤逻辑对照

实际代码（`dataset.py` 已重构为门面，真正过滤在 `data/reader.py:71-76`）：

```python
# data/reader.py:71-76
def filter_is_trading(df: pd.DataFrame) -> pd.DataFrame:
    before = len(df)
    df = df[df["is_trading"] == True]
    print(f"[ParquetDataset] 过滤 is_trading False: {before:,} -> {len(df):,} (drop {before - len(df):,})")
    return df
```

- **停牌合成行（`is_trading=False`）100% 被过滤掉**，不进任何训练窗口 —— 已由全量 268,313 行验证（`is_trading=True` 命中 0）。
- **但过滤后不是「删除该日」而是「该日不存在」**：滑动窗口是在过滤后的序列上连续取 60 行，所以**跨停牌的两段行情会被拼接成连续的 60 天**，模型看到的「过去 60 个交易日」实际可能跨越数月的真实日历时间，停牌期间的信息完全消失、且没有任何标记。
  - 例：002265.SZ 2021-11-22~12-03 停 10 天，过滤后 2021-11-19 与 2021-12-06 在序列里相邻。
  - 这是设计选择（`AGENTS.md` 的 `filter_is_trading` 语义），但**建议在报告里显式记录**：它不是「停牌日被当作缺失值」，而是「停牌日被整体删除，窗口时间轴被压缩」。
- 反向检查：`filter_is_trading` 只过滤 `== True`，**不检查价格有效性**，所以 §4 的零价 73 行会穿过去。

### 4.2 对窗口 warmup 的影响（这是个真实且可量化的边界效应）

`data/reader.py:79-104` 的 context warmup：`start_date` 之前取每只码最后 `max(seq_len-1, 1)` 行（默认 `seq_len=60` → 59 行）作为 `_transform_context=True` 输入；`reader.py:363-365` 要求 `n >= seq_len + horizon + 1`（默认 60+10+1 = **71 行**），不足则**整只码跳过、0 个样本**。

因为上市前没有行，所以「2021 年后上市」的股票在早期 role 里的可用行数 = `listdate` 之后的交易日数。实测：

| role 区间 | 有行的码 | 可用行数 (context+eligible) < 71 而被整只丢弃 | 说明 |
|---|---|---|---|
| training `2013-01-01~2025-06-30` | 5,199 | **102 只** | 全部是 `listdate > 2025-05` 的新股（如 001220.SZ 2026-02-03 → 0 行；001221.SZ 2025-07-30 → 0 行） |
| validation `2025-07-01~2025-12-31` | 5,199 | **64 只** | 如 001233.SZ 27 行、001285.SZ 61 行、001325.SZ 10 行 |
| test `2026-01-01~2026-08-31` | 5,199 | **3 只** | 600146.SH / 600240.SH / 600565.SH 各 59 行（退市股，末行早于区间，只有 context） |

两个具体后果：

1. **训练早期（2013 年）的截面股票池是「当时的真实池 + 未来才上市的码不存在」**，这是正确行为（无未来信息泄露）。
2. **验证/测试集的 warmup 会被新股削弱，但不会污染标签**：`valid_starts` 用 `is_context[label_pos]`（`reader.py:376-382`）保证 context 行绝不作标签日。所以上市晚的股票在验证期只是「样本更少」，不会把上市前当标签。
3. 值得记录的边界：**上市首日附近 `relative_transform` 的第一行分母 `close[t-1]` 为 NaN**（`transform_kernel.py:29`），P 组首行被填 0，等价于「无历史」。这是既有设计，不是本次新发现，但对「2021 年后上市」的样本占比越来越高（2945/5199 = 56.6% 的码首行在 2014 之后）这件事，应当知道。

### 5.2 根因已定位到源头（不是训练导出引入）

- **`Z:/dev/kline/day` 和 `Z:/dev/kline_adj/day` 源头文件里就是 OHLC=0**：全库 footer 扫描（5,215 个文件的 `open` 列 min 统计）找出 43 个文件 min(open)<=0，逐只读行确认 **共 172 行 OHLC 全 0，全部在 2026-08-06 ~ 2026-09-17**。
- 逐对连 `history_status`：**172/172 全部命中，其中 171 行 `是否停牌=1`，1 行（301117.SZ 2026-08-24）`记录类型='touch'` 且有涨跌停幅度 0.2**。
- 即：**停牌日的 bar 被写成了 0.0 而不是「不写 bar」或 NaN**。quant 报告 §2.1 说「停牌日不会写进 kline/day」，这个规则**在 2026-08 之后被打破了**（可能是新加的补齐逻辑或上游 SDK 返回了 0 值行）。同一天 `Z:/dev/kline/day/600984.SH.parquet` 在 2026-08-11~08-24 有 9 行 `open=high=low=close=0, volume=amount=0`，而 08-10 与 08-25 是真实价，中间正好是停牌段。
- 训练导出侧不做零价校验（`export_training_data.py:585-596` 只 merge + `volume.fillna(0)`），所以 `is_trading` 判定用的是「该日是否在 kline 行集合里」→ 有 0 值行 → `is_trading=True`。零价就这样进了训练文件。

### 5.3 过滤逻辑到底覆盖了没有？——**没有，AGENTS.md 那句是错的**

- AGENTS.md：「`dataset.py:164-165` 强制过滤 `is_trading=True` 且 OHLC 全 0/NaN 的行」。
- 实际 `data/dataset.py:164-165`（当前行号 164-165 对应 `filter_is_trading` 必须为 True 的断言）：
  ```python
  if not config.filter_is_trading:
      raise ValueError("filter_is_trading 必须为 True，禁止将合成行用于训练/评估")
  ```
  **这里只是拒绝 `filter_is_trading=False` 的配置，没有任何零价检查。**
- 全仓 grep `ohlc|all_zero|open.*> 0|price.*valid` 在 `data/` 下**没有零价过滤实现**；唯一的零价语义在**回测侧** `backtest/cnn_adapter/market.py:191-196` 的 `_optional_price()`（`price <= 0.0 → None`），以及 `research/goal_repro` 的 commit message 提到的「fix: market 零价行转 None(防core除零, F60实测73行)」——**那是回测适配器的修复，不是训练数据的修复**。
- 所以：**73 行零价在训练链路上是「活的」**。

### 5.4 实际影响（定量，不是推测）

按 `reader.py` 的建窗规则（`filter_is_trading` 后连续 60 行、`horizon=10`、`n>=71`）对 26 只零价码逐只重建窗口：

| 项 | 数值 |
|---|---|
| 26 只码的合法窗口总数 | 64,192 |
| 窗口内**含至少 1 个零价行** | **31 个**（0.048%） |
| **标签日恰为零价行** | **6 个** |
| F60 全库估算合法窗口总数（`Σ max(0, n-70)`，n=5199 只的 `is_trading=True` 行数） | 11,596,085 |
| 31 / 11,596,085 | **0.00027%** |

具体伤害路径（已用 600984.SH 实测）：

1. **特征污染**：`relative_transform` 用 `x/close[t-1]-1`（`transform_kernel.py:27-31`），`close[t-1]=0` 被 `previous != 0.0` 挡住 → 该行整列变 NaN → `apply_column_rule` 兜底填 0（`:61-62`）。零价行本身被填成「中性 0」而不是缺失标记，**且共享 `g9_observed_mask` 只覆盖 18 个 G9 列，不覆盖 P 组价格**，所以下游无法识别这是伪造的中性值。
2. **标签污染**：`_future_ret_open_open`（`data/labels.py:12-15`）要求 `base > 0`，零价作 base 的位置被置 NaN → 该位置不出标签（这部分是**安全的**）。但**零价作 target 的位置不会被拦**：`target[t]/base[t]-1 = 0/prev-1 = -1.0`，于是产生 **`return_10d = -1.0`（-100%）的假标签**。实测 F60 里 `is_trading=True` 且 `return_1d=inf` 的 21 行、`return_10d=-1.0` 的 71 行、`return_20d=-1.0` 的 73 行 —— 与零价行数（73）精确对应。
3. **`return_1d=inf`**：21 行 `is_trading=True` 的 `return_1d` 是 `inf`（分母为 0），不是 NaN。这些 inf 会进 `cs_rank`/`mkt_factors` 的截面统计（`cs_mkt.py:79-81` 有 `np.isfinite` 保护，所以市场因子**安全**；但 `return_*` 若被当作特征则不安全）。
4. 结论：**这 73 行的量级（0.00027% 窗口）对模型训练结果无实质影响**，但它是「过滤逻辑缺失」的证据，且**同类问题在 2026-09 之后的干净考场数据里会持续出现**（源头 172 行分布在 2026-08-06~09-17，且 2026-09 后仍有 8 只码在产生零价行）。
