- **解法（分三步，每步可独立验收）**：
  1. **判据先落地**：定义 `decision_eligible(event)` ＝ `announcement_date ≤ cutoff`（且版本可溯源）；无时刻时按"公告日当日 23:59:59 视为已知"的**保守边界**，并显式记录 `boundary_policy="conservative_eod"`。写进 docstring + 单测，不进代码前先评审判据。

  3. **接线**：`_load_prepared_window` 传 eligible snapshot；`CorporateActionContext` 让 `window_end` 真正参与过滤；`fractional_scenarios.py:107-111` 的 `certification="NOT_CERTIFIED_CONDITIONAL"` 改为**由实际能力驱动**的枚举（有 asof 则是 `CERTIFIED_ASOF`，否则仍是 conditional）。
- **关键约束（防止又变成"条件情景"）**：W1 的 300502 是**公告在 cutoff 前、ex 日在 cutoff 后**的反例，任何"按 ex 日剪裁"的实现都会删掉它并得出错误结论。所以**过滤键必须是 announcement/known_at，绝不能是 ex_date**。这是 v3 已经踩过的坑（`ANALYSIS.md`）。
- **前置**：无外部依赖；但需要 owner 拍板 `boundary_policy`（这是唯一的主观项）。
- **解锁**：W1 从"永远条件情景"变成"可以报 PIT 合格"；同时给 P2 的干净考试提供同一套 asof 机制。

### 候选线 A：W2 四策略的"证据资格补强"（推荐先做，成本小）

- **假设**：W2 的 B1/S1/S2/C70 四个数字**本身是对的**（NAV 恒等式 2.33e-10 已独立复核），当前 `INCOMPLETE` 只源于**证据资格**（PIT/税务/CA 来源/coverage），而非账簿错误。若把资格缺口逐项量化，其中一部分可被"限定性陈述"吸收，而不必等所有缺口闭合。
- **验证方法**（只做已有材料，不重跑模型）：
  1. 从 `staged_mechanical_results_20261028_v1` 逐策略重算：逐日末正持仓数峰值、现金/NAV、费用/滑点拆分、沪深 300 同期 NAV、清算状态、成交笔数。
  2. 对 coverage 缺口（W2：missing 15,620 / unknown 16,605）做**敏感度实验**：把 unknown 状态分别按"可交易"与"不可交易"两种极端假设重算这 4 个数字，报告区间。这是把"不知道漏了什么"变成"**知道最坏是多少**"的唯一低成本办法。
  3. 输出一张四策略并列表（B1/S1/S2/C70 **四行都必须出现**）。
- **通过标准**：① 四策略并列表可复算（脚本入库）；② 敏感度区间**下界仍 ≥ 0 且仍 > 沪深 300** → 则该窗口可升级为"限定性通过（限：税务为 20% 压力情景、coverage 为 unknown 区间）"；③ 任一策略下界 < 0 → 明确写"该策略在 W2 不成立"。
- **预计成本**：8~12 小时（无重训、无外部依赖）。
- **它能证明什么/不能证明什么**：能证明"W2 不是账簿错误"并给出**最坏情形**；**不能**取得达标资格（W2 是 2021H2 历史窗，不属脏考；且税务/来源仍非认证）。

### 候选线 B：干净考试 harness 的"空跑演练"（推荐与 A 并行准备，但**不产生业绩结论**）

- **假设**：即使没有 2026-10 后的行情，也可以**现在就把考试流水线搭好并用历史数据空跑**，使"行情一到就能出结果"，避免到时才发现流程缺陷。
- **验证方法**：
  1. 定义考试契约：`exam_start`（≥2026-09-01）、`train_end < exam_start`、信号生成时刻早于订单日、四件套（冻结信号/连续账本/同期基准/独立复核）的打卡点。
  2. 写 `scripts/exam/`：① `freeze_signals.py`（生成信号→立即落盘+哈希+时间戳）；② `run_ledger.py`（逐日运行，产出 `daily_account.jsonl`/`orders_fills.jsonl`）；③ `verify_exam.py`（四要件检查，缺一 fail）。
  3. **用 2021-07~12（W2 区间）做一次空跑**，验证三件事：信号冻结哈希可复算、账本逐日连续无缺口、基准对齐到同一交易日集合。
  4. 把"烧样本守卫"接进来：任何 `exam_start`/`test_start` 落在 2026-01~08 的运行，**默认 raise**，需显式 `--allow_burned`（该参数名要出现在产物里）。
- **通过标准**：空跑产出的台账通过 `verify_exam.py` 的四项检查，且 `--allow_burned` 守卫有测试；**并且**空跑结果**明确标注为"harness 演练，非绩效验收"**。
- **预计成本**：1~2 天。
- **关键约束**：这条线**不许**输出"策略在 2021H2 表现如何"的结论——那会变成第二次拿 W2 当业绩。

### 候选线 C：≤10 持仓下的低换手政策族（真正的目标推进，成本中~大）

- **假设**：在 ≤10 硬约束下，**唯一没被证伪的方向是"截面 α 排序 + 低换手惯性 buffer"**（Q1 §3.3 负面清单之外，唯一还有正向方法线索的区域：`goal_repro` 的 `s100+惯性 500` 两折 +59.5%/+8.3%，但 100 只持仓不可用；`ATTRIBUTION` 显示 exitnp 换手 17.9× vs b500 48.6×）。假设是：**把 buffer/惯性机制搬到 6~10 只持仓上，能显著降低换手，从而让成本后为正**。
- **验证方法**：
  1. **预注册**（写死在跑之前）：出场规则只用两类——`buffer`（排名跌出 N+b 才卖）与 `hold_min_days`；入场只用 top-k（k∈{5,6,8,10}）。**参数网格必须很小**（≤6 组），否则又变成事后扫描。
  2. 在**已冻结的历史窗**（W2 2021H2 与另选一个未参与调参的窗，如 2019H2）上并列跑，**两窗都必须报告**。
  3. 必须做**行业约束**（单行业 ≤2 只）与**成本敏感度**（费率 ×1/×2/×3）。
  4. 用候选线 B 的 `verify_exam.py` 检查账本连续性。

- **预计成本**：3~5 天（含 2 个窗运行）。
- **为什么值得做**：它是唯一还能改善"成本吃 alpha"这一结构性问题的杠杆（Q1 共性 C：崩点全在执行侧）。而且**预期不能太高**——若两窗不一致，就应当接受"历史窗已无法支持任何政策"，全部筹码押到干净考试。
